# CrazyPod 2026 · 产品设计方向 v0.1

> 状态：设计基线 / 待原型验证。适用目标：iPod Classic 6G/6.5G/7G，320×240、Click Wheel、64 MiB RAM。
> 原则：先定义体验，再决定实现；本文不宣称通过真机测试。

## 1. 一句话定义

CrazyPod 是一台**专注本地音乐的现代 iPod**：像经典 iPod 一样直接、可靠、可盲操作；像 2026 年的优秀消费电子产品一样克制、清楚、细致。

不把设备变成小型手机。不以应用数量、动画数量或配置项数量衡量产品完成度。

## 2. 不可妥协的五条原则

1. **音乐永远在第一层。** 不进入复杂桌面，也能迅速看到正在播放与音乐库。
2. **一个操作只有一个明确结果。** Click Wheel 滚动用于当前页面最主要的动作；中键确认；Menu 返回；播放键在所有安全场景中控制播放。
3. **封面是内容，不是装饰。** 显示真实专辑封面；没有封面时使用克制占位符，不制造虚假的媒体内容。
4. **安静比炫目重要。** 动画解释层级与方向；不影响音频实时性，不强迫用户等待交互完成。
5. **可靠性是设计的一部分。** 开机、续播、耳机、USB、低电量与异常恢复必须有明确状态和回退路径。

## 3. 主导航结构（正式版）

主界面仅保留四个一级项目，顺序固定为：

1. **正在播放**（若当前无歌曲，则显示「开始播放」或上次播放入口，不出现空白页）
2. **音乐**：专辑 / 艺术家 / 歌曲 / 播放列表（含收藏）/ Cover Flow / 搜索 / 随机播放
3. **播客**：作为音频内容保留，可在音乐库中互相跳转；不构建网络客户端
4. **设置**：声音 / 播放 / 显示 / 语言 / USB / 电源 / 关于

软件锁屏和时钟属于系统状态，不作为普通应用。随机播放属于音乐行为，不作为桌面应用。外观偏好属于设置，不作为桌面应用。

正式版首页**不再使用 17 应用横向图标轮播作为主要导航**。原图标轮播可保存在实验构建，但产品首页采用信息密度更高、可直接操作的列表及上下文预览。

## 4. 正在播放（首要设计对象）

目标：拿起设备就知道**听的是什么、是否播放、如何继续**。

内容优先级：专辑封面 → 歌曲名 → 艺术家 → 播放进度 → 播放状态。专辑名称与音质信息为次级信息。

交互合同：
- 中键：打开有边界的歌曲操作菜单（收藏、加入播放列表、播放模式、歌词）。
- 滚轮：默认调节音量，显示短暂、明确的音量反馈；不得意外跳曲。
- 左右键：上一曲、下一曲；长按寻轨按现有设备习惯处理。
- 播放键：播放/暂停；长按电源菜单的既有安全路径不改变。
- Menu：返回音乐库；从其他页面可以快速回到正在播放。
- 歌词：作为明确切换的专用模式，不常驻侵占封面空间。

封面与歌词刷新不能导致音频丢帧。没有缓存的封面先保留稳定的占位/上一张封面，不显示反复闪烁的加载动画。

## 5. 视觉原则

- **底色**：黑、深灰、暖白三种层级即可；避免在所有控件叠加霓虹、辉光、玻璃效果。
- **强调**：一个动态内容强调色或固定强调色，不在同一屏使用多种竞争色。
- **排版**：标题优先可读，曲名能完整识别；行高、列表选中态、对齐与截断要统一。
- **运动**：仅在页面切换、选中变化、封面切换时提供必要反馈。尊重「减少动态效果」。
- **一致性**：保持一套旗舰默认外观；最多提供「经典 / 现代」两套官方视觉预设。保留其他主题开发成果，但不要让它们定义正式版的质量。
- **可用性**：不得把低对比度、微小文本、持续滚动文字或频繁转场当成现代感。

## 6. 功能裁剪：不是删除源码

| 归属 | 正式版处理 |
| --- | --- |
| 音乐、播放列表、收藏、搜索、歌词、Cover Flow、EQ、USB、锁定、电源 | 核心保留、优先验证 |
| 播客 | 保留本地文件播放，降低桌面权重 |
| 壁纸和少量外观设置 | 收入设置 |
| 相册、视频、图书、备忘录、日历、联系人、运动、秒表 | 移出正式版导航；下一阶段评估是否排除正式版构建 |
| GB/GBC、Mini Apps、AOT 主题运行时 | 转入 **CrazyPod Lab** 产品实验模式；不作为正式版的稳定性前提 |

**禁止以隐藏入口伪装成代码裁剪。** 先保留旧数据及兼容路径；之后分阶段通过独立构建选项裁掉模块、资源和初始化，逐项验证编译与运行。

## 7. 代码层面必须先保护的事实

当前 `crazypod_apps.h` 的应用 ID 已持久化，`CRAZYPOD_APP_COUNT` 为 17。
`crazypod_apps.c` 的 `default_order`、`menu_enabled_mask`、`crazypod_apps_restore()` 与 `crazypod_apps_is_fixed()` 都会影响可见应用；特别是 Music、Customize、More Features、Settings、GB/GBC 属于强制可见类型。

因此：
1. 不重用、重编号旧应用 ID；不破坏已有配置格式。
2. 不能只调整 `default_order` 就声称完成新导航。
3. 给旧配置与新正式版导航建立显式迁移/映射；独立测试新装、升级、恢复默认、隐藏应用及异常状态。
4. 保持 Music、Shell、Presentation、Platform 现有模块所有权与依赖方向；不要为了重设计引入跨模块私有头依赖。
5. 保留 Click Wheel 原生渲染和 TE 同步约束；不能用简单限帧掩盖撕裂问题。

## 8. 分阶段交付（每一步可撤回）

### 第 0 步：设计冻结与验收用例
- 锁定四个一级项目、音乐库内容结构、按键语义、Now Playing 信息优先级。
- 保留现有主线；所有实验在独立分支。
- 用模拟器截图/录屏与真机交互记录审查，而不是凭配置项多少衡量完成度。

### 第 1 步：首页原型（仅切换入口和布局）
- 制作 320×240 的列表型主页，保持当前 Rockbox 音频、USB、存储、电源实现不动。
- 不删除任一功能模块；实验性旧应用暂时保留回退入口。
- 验证：首次启动、旧配置恢复、滚轮连续滚动及反向、Menu/Select/Play、显示刷新。

### 第 2 步：Now Playing 与音乐库
- 统一封面、元信息、进度条和播放状态。
- 验证歌曲切换、封面缺失、超长标题、多语言、歌词、音量与后台播放。
- 验证大量歌曲与专辑时的列表响应与增量扫描，不允许阻塞音频。

### 第 3 步：实验模块隔离
- 设正式版/Lab 构建配置；逐步排除非音乐应用代码和资源。
- 明确检查最终二进制、资源包、持久化兼容、恢复路径。
- 独立测试 Lab 运行时不能破坏正式版状态。

### 第 4 步：真机质量门
- 开机/重启/异常掉电/状态恢复；长时间连续播放；充电与 USB 数据模式切换。
- HDD/SSD 等存储适配器分别验证，不能仅以编译成功替代。
- 验证 LCD 撕裂与滚轮跟手、内存稳定性、电池消耗与低电量行为。
- 明确记录测试型号、固件 hash、设备配置、结果和未覆盖场景。

## 9. 产品验收指标（设计目标，非已测成绩）

- 从主页进入「正在播放」：**最多一次确认**。
- 从主页进入歌曲/专辑浏览：**最多两次确认**。
- 全局播放/暂停不依赖打开某个应用；播放过程无音频中断。
- 页面切换不要求等待非必要动画结束。
- 所有操作都有明确反馈与 Menu 退出路径。
- 正式版默认界面不得出现空入口、实验功能或占位应用。

## 10. 明确不做的事情

- 不做 Wi‑Fi 串流、App Store、社交功能、云账号、手机通知或伪装为 iPhone 的桌面。
- 不增加现有硬件不具备的蓝牙/无线能力承诺。
- 不为了外观将底层可靠代码一次性重写。
- 不未经真机测试就宣称稳定发布。

---

**设计评审结论：** 先做少而强的音乐体验，再决定保留哪些实验能力。若用户无法在不学习的前提下完成播放、查找、收藏与续播，则任何额外功能都不应进入正式版首页。

## 11. 2026-11-17 · 音乐库 Shuffle 入口修复

- 4 项产品 Home 保持不变；在 Music 根菜单增加已本地化的「Shuffle」动作，避免原 17 应用桌面退役后失去随机播放入口。
- 复用原有异步全曲库随机播放实现，避免在 LVGL 回调中同步扫描文件；空曲库时反馈「No track available」。
- 保留旧 Music 路由索引和持久化应用 ID；Shuffle 是独立动作而非伪造第九条路由。
- 仍须在 ARM 构建、320×240 模拟器和 iPod Classic 6G 真机验证（包括无媒体、首次扫描、持续播放和 Menu 返回）。
