# CrazyPod · Apple-like Native UI v1

> 设计对照：用户已确认的 Home / Music / Now Playing / Controls / Settings 五屏概念稿。基于 Rockbox / LVGL 9.5 / iPod Classic 6G 的 320×240 RGB565 真正固件源代码，不代表已有与概念稿逐像素相同的真机截图。

## 目标

从“卡片很多的自定义播放器皮肤”转为“像 iPhone 的原生音乐/设置界面，同时保留实体 Click Wheel 的 iPod”。设计是风格借鉴，不混淆苹果官方的素材使用权；个人内部图标统一由 `CRAZYPOD_PRIVATE_ICONS_DIR` 提供、正式构建使用原创图标回退。

## 2026-11-17 追加：2025 概念风格 Home 与专辑自适应背景

用户指定上传的 iPod classic 2025 概念图**左侧第一台设备**作为 Home 视觉参考，并明确要求应用**上下滚动**：

- 在 `49..171px` 的裁剪视窗中，4 个应用对象保持真实垂直顺序（Now Playing、Music、Podcasts、Settings）。
- 当前选中应用固定到屏幕视觉中心 `y≈87px`，成为宽 `278px`、高 `46px` 的白色浮起卡片；其他应用更窄、更低透明度，只从上下边缘露出部分。音乐应用默认居中，仿照参考图的初始焦点。
- Click Wheel 每个有效 detent 使整条轨道上下偏移一档 `53px`；旧卡片与新卡片的文本、尺寸及图标比例只更新两次，整条轨道仅 `lv_obj_set_y()` 一次。没有左右轮播、PNG 重解码、新音频线程、网络访问或触摸手势。
- 实体中央键仍选择当前应用，左右/长按、Hold 以及画面提交 TE 栅栏保持原逻辑。为保证 50ms 响应目标，先采用即时跟手的纵向步进而非高耗电的连续惯性动画；动画效果需要实机测量后才决定是否增加。
- Home 迷你播放器仍位于 `y=181px`，与应用视窗留出 10px 间隔。背景为克制的浅蓝白，焦点以阴影/文字层级体现；用户提供的 Music/Podcasts/Settings 图片继续只在私有内部构建中载入。

**播放界面**：并非随机切换预设背景。固件原有缓存会在封面切换时将 RGB565 封面缩采样到 40×30、做两次 5-tap 模糊，并放大成 320×240 的背景；本轮进一步从同一张封面提取真实主色，计算每通道 8–84 的暗色调，叠加到模糊背景上，同时使用**叠加后颜色**重新测量文字区域亮度，决定黑/白字幕。提取仅发生在封面变化/代际更新时，无每帧调色和额外整屏缓存。没有封面则回退为根据曲目元信息生成的温和色系。

**验收**：先检查多语言菜单副标题、本机 320×240 的裁剪边界、阴影与底栏重叠、滚轮连拨的首帧延迟；再检查暖/冷封面更换的背景颜色与白色封面的文字对比度。是否达到参考效果/设备指标，仍需模拟器画面与实体设备进一步确认。

## 需要继续实机验证

- 320×240 LCD 上 14px 菜单图标、字色和小选中背景在真实色深与背光下是否清晰。
- Home 滚轮选择到画面呈现的 P95 延迟（目标仍为 ≤50ms，未测），快速滚动与 Hold 释放后的缓存一致性。
- 仍通过已有字幕、音频、USB、低电量和锁定行为测试；不得通过改变 LCD TE / I2S / 解码时序来做视觉补偿。
- 当前每个根菜单的 7 个入口使用 **6 行可见滚动窗口**，不是概念图中一次显示 7 行；按现有滚轮导航与内存约束保留。
- 本轮不触及主题数据格式与音频持久化，也没有把用户上传的官方风格图标写回公开 Git 仓库。

## 验证原则

宿主 C99 + 静态契约检查、iPod 6G ARM 固件链接、macOS 模拟器都必须重新通过。历史 macOS CI 曾在 Make 3.81 下报 `firmware/crt0.o` 缺失，不能将 ARM 成功误报为模拟器也成功。PR 保持 Draft；未刷机。概念图不是实机拍照。
