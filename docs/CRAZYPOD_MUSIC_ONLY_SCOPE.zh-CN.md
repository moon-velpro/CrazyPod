# CrazyPod 2026 · 纯音乐设备精简方案（执行中）

**决定**：CrazyPod 不再以“能运行 17 款应用”的通用掌上 OS 为目标。它是基于 iPod Classic 6G 的 **离线音乐播放器固件**。

## 保留（真正必要）

1. **音乐**：本地索引、艺术家/专辑/歌曲/播放列表、搜索、Cover Flow、封面、歌词、播放队列、随机和循环。
2. **播客**：本地文件/音乐库支持的播客音频播放。不假装存在网络、云服务或硬件无线功能。
3. **系统设置**：音量、EQ、显示亮度、语言、时间、电源、睡眠定时器、USB 储存与必要的输入设置。
4. **设备生命线**：Rockbox 音频核心、Click Wheel、LCD/TE 同步、Hold/锁屏、硬盘/SD 和 USB、恢复/升级路径、音乐播放状态与内存保护。
5. **必要的内部素材能力**：真实专辑封面与低开销显示背景。可以保留兼容已有壁纸的读取器，但无需完整相册应用。

## 删除（不再作为 CrazyPod 的应用）

Game Boy 游戏模拟器、第三方 Mini Apps/CPK 应用商店和运行时、相册/视频浏览器、电子书阅读、笔记、联系人、日历、运动、秒表、独立时钟应用、复杂主题预设编辑器，以及所有仅为这些应用存在的图标、注册表、预览、资源与缓存管线。

注意：**睡眠定时器、时间显示、锁屏、必要的音频图像解码器可能复用这些模块中的底层代码。** 删除的是应用，不是盲目删除所有重名文件。跨模块依赖须逐个确认。

## 实施方式

本次在 **独立分支** `refactor/music-only-2026` 开发，不直接修改主线或正在进行视觉验收的 `design/music-first-2026`。

**第一步（已提交）**：
- 3 款产品应用白名单：Music / Podcasts / Settings；Shuffle 与 Lock 是设备操作，不作为应用。
- 旧枚举 ID（例如 Music=1、Podcasts=2、Settings=14、Game Boy=19）继续保留用于读取旧状态，不重新分配数值。
- 移除 Game Boy 引擎与 UI 的 4 个编译单元，并从 Git 删除它们及专属头文件/构建文件；清理 8 种本地化中 11 项已退役文本及生成表。
- 旧应用在 Launcher 层被阻止进入；不能仅靠删除 Home 图标来假装精简。
- `tests/crazypod_product_scope_host_test.c` 检查入口白名单与 ID 兼容。

**下一步（需按实际依赖分批清理）**：
- 首先剥离非音乐运行时服务（Mini Apps/CPK、模拟器、笔记、电子书、图库/视频及组织工具）。
- 再移除这些服务的路由、输入分发、界面和构建源文件，修订国际化表。
- 每个拆除批次都进行 ARM 固件与模拟器构建，测试并报告固件大小/内存占用的变化。
- 最终简化 `crazypod_apps.c` 持久化管理，但仍保留旧状态兼容读取，不能将老用户的设置误解析为新应用。
- 无需主动删除用户 SD/HDD 中的 `/Books`、`/MiniApps`、`/Pictures` 或任何其他旧应用目录；卸载固件功能不等于删除用户文件。

## 阻止合并的条件

只要存在以下情况就不合并、不烧录：无法通过 CI，音乐播放/封面/索引/USB 被破坏，启动重启异常，真实滚轮操作有误，或者内存占用与目标不符。构建成功不是实机安全证明。

**验收标准**：功能确实从最终二进制中消失（不能仅隐藏 UI）；音乐与设备生命线不受影响；开机、打开音乐库、切歌、返回和休眠流程明显更直接。

## 安装包收缩（已提交，待最终完整 CI 验收）

- 移除独立 MiniApps/CPK 构建 Make 目标，以及不再需要的 Node/npm 打包工具链；原生音乐固件的构建命令保留。
- 正式 `CrazyPod-6G.zip` 只创建 Music、Podcasts 内容目录及必要的 `.rockbox`；停止创建 Books、Pictures、Videos、Contacts、Calendars、MiniApps/Games 的空目录与安装 CPK。
- 模拟器构建不再生成或复制退役小游戏、AOT 主题等 CPK。
- Git 删除 11 个已构建 CPK 分发文件，以及失效的 Game Boy 用例和 README（可通过历史提交恢复）。
- 新建包验收测试，阻止应用插件再次混入构建与发布包。

**注意**：目前固件源清单 `apps/SOURCES` 中仍包含部分旧应用运行时模块；它们还需逐批做真实代码与依赖移除。请勿将现在的成功编译等同于全量精简完成。

## 2026-11-17 · 启动与入口依赖实际收缩

- 将 Hosted/ARM 两条启动路径中笔记、电子书、运动记录的初始化调用移除，避免用户只想听歌时读取这些已退役的数据；保留 `crazypod_music_init()` 及音频、磁盘、电源、USB 初始化顺序不变。
- 从原生应用 Launcher 实际删除退役应用的 `case` 分支与关联包含；目前只分发音乐、播客、设置、Shuffle 及 Lock。旧 ID 仍保留在持久化结构中。
- 加入静态回归断言覆盖两条启动路径及 Launcher 最小白名单；**这不是 ELF 二进制彻底裁剪的证据**，一些退役功能仍由旧路由和 UI 运行时直接引用。
- 路由系统剩余深度耦合、默认主题读取、模拟器与 ARM 构建/真机验收仍未完成，PR 持续保持 Draft。

## 2026-11-17 · 与视觉分支同步音乐库随机播放

- `refactor/music-only-2026` 已按文件级兼容校验，同步 `design/music-first-2026` 的 7 项音乐菜单（专辑、艺术家、歌曲、播放列表、Cover Flow、搜索、Shuffle）、路由映射、播放动作及宿主测试。
- Shuffle 不是新的应用或持久化旧路由：使用已有异步音乐库扫描、曲库随机播放流程，与现有产品白名单 `CRAZYPOD_APP_SHUFFLE` 一致。
- 后续需要在完成代码拆除后将该精简分支与最新设计父分支正式对齐，再由最新 HEAD 的 ARM、模拟器、用户数据回退与真机测试判定是否能合并。

## 2026-11-17 · 首轮较大规模的真正二进制裁剪

- 从 `apps/SOURCES` 中删除 7 个视频相关编译单元与整组 MPEG-1/2 解码、线程、输出实现（共 24 行组件/平台条件定义）；不再将原先 Video Engine/MPG 视频解码代码链接到音乐固件。保留安全的 `crazypod_videos_disabled.c` 空实现用于尚未清理完毕的旧 UI 符号兼容，所有视频路径/海报为空、播放返回不支持、删除永远失败且无文件 I/O。
- 此次裁剪不触及 Rockbox 音频解码核心、PCM、存储驱动及专辑封面使用的图像接口。播放器原本就没有视频导航入口，因此不再创建视频资源或打开视频文件。
- `crazypod_now_playing_theme.c` 改为只支持内建播放器的兼容层：不再读取或写入旧 CPK 主题配置，不初始化或打开外部主题。旧用户主题数据原封不动留在磁盘中。
- `crazypod_runtime_services.c` 不再按帧轮询 Mini Apps/CPK 安装、虚拟闹钟、照片/视频、笔记、图书和组织管理服务；保留音乐增量扫描、音频状态、封面缓存、LVGL 动画、锁屏时的状态保存及安全轮询。主 UI 也不再初始化 MiniApp Runtime。
- 构建增加 `nm` 产物检查，`rockbox.elf` 若出现 MPEG2 或视频引擎/目录符号会直接失败；C99 宿主测试覆盖禁用视频接口。源清单与启动调用的静态契约亦加入回归测试。
- **验证边界：** 当前已通过禁用视频接口的隔离 C99 编译/执行，以及 GitHub 源码静态检查；最新 ARM 全量固件、macOS 模拟器以及真机测试暂未确认通过，不应将本节视为可烧录证明。未在已验证固件上量出节省的字节数。

## 2026-11-17 · 第二轮：UI 路由与启动路径去耦

- `crazypod_feature_input.c` 仅为 Music、Now Playing 和 Settings 注册输入分发器；不再把按键/转盘输入送往 Notes、Books、Media、Organizer、Customize 或 MiniApps。
- `crazypod_route_query.c` 与 `crazypod_route_renderer.c` 不再查询、渲染旧应用的菜单、图标和全屏界面；Now Playing 始终采用内建原生播放器。后续还需要拆除旧的 `crazypod_route_actions.c` 和组合根中的全部依赖，才能从 `apps/SOURCES` 排除这些应用的剩余源文件。
- 添加 `crazypod_route_registry_product_allowed()`：合法产品路由只有 Music、Now Playing、Podcasts 和 Settings 所属的路由。旧的路由枚举值、记录描述符保留不变，但启动器根路由、路由入栈与激活入口均拦截旧应用。现有 C99 路由宿主测试扩充了音乐/设置允许与图书/媒体/MiniApp 拒绝的断言。
- `crazypod_ui.c` 不再启动相册/视频目录，也不再为已退役媒体任务保持 CPU Boost。用户已选择的壁纸和音乐封面依然会初始化。
- `crazypod_main.c` 的 ARM 和模拟器分支不再读取 DIY 预设库；保留独立的已保存外观设置和音乐库初始化，不删除旧文件、不改变持久化编号。
- GitHub Actions 新增对以 `main` 或 `design/music-first-2026` 为基线的 PR 执行合同测试、ARM 固件和 macOS 模拟器构建的事件配置。该事件配置不代表最新 CI 已成功；当前仍缺少最新提交的完整构建产物与真机稳定性证据。

**重要：** 这轮削减了产品入口和 UI 主循环依赖，并不意味着其余旧模块已经全部从 `rockbox.elf` 移除。应以 ARM 链接映射、ELF 符号与真机播放/USB/待机/恢复测试为最终裁剪依据。

## 2026-11-17 · 旧横向 Home 图标缓存裁剪（本轮）

- 当前产品 Home 使用 LVGL 纵向四应用卡片和预生成的小型 RGB565A8 图标；不再调用旧原生横向图标轮播。
- `crazypod_icons.c` 移除了原有 **17 × 160 × 160 × 4 = 1,740,800 B** 的 BMP RGBA 常驻槽位，不再在开机时顺序打开 17 个 BMP 主题文件。保留旧导出函数的无 I/O 空实现，以免与其他待拆除模块产生链接回归。
- `crazypod_desktop_native.c` 移除了旧轮播 **17 × 120 × 120 × 4 = 979,200 B** 的图像缩放缓存，以及已不再使用的 **320 × 103 × 2 = 65,920 B** 绘制底图。仍保留弹窗、Hold 和 Now Playing 使用的独立 320 × 103 RGB565 underlay 及其复用接口。
- `crazypod_ui.c` 不再调用退役的图标主题初始化；UI 宿主构建范围检查防止这些缓存和开机文件访问重新引入。
- **源码级共删除 2,785,920 B（约 2.66 MiB）的静态数组声明，不等于已证明的实机 BSS/峰值内存节省。** 编译器/链接器此前可能已通过段垃圾回收剔除未引用对象；必须对比新旧 ARM ELF map/BSS 和设备可用内存才能量化真实收益。
- 不改音乐编解码、EQ、封面解码、USB、LCD/TE、Click Wheel 输入、休眠/恢复或用户盘上的任何图标/音频文件。新的小型个人图标素材仍仅通过本地 private pack 注入，不进入公开仓库。
- 本轮最新提交的 CI 宿主合同和 UI 宿主测试已通过；ARM 固件、macOS 模拟器及真机仍须以本轮最新 HEAD 独立验收，保持 Draft，禁止据此直接烧录。
